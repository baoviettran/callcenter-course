Browser Integration

sip.js-worker + shared.io — the softphone and data layer that survive tab switches.

Closing a tab shouldn't kill a call

You know that feeling when you accidentally close a browser tab during a call and the call drops? This system fixes that.

The softphone runs in a SharedWorker — a background thread that survives tab reloads. And there is a second SharedWorker that keeps your WebSocket connection alive across all tabs.

Let's see how both work.

📡

sip.js-worker

Runs the SIP phone engine in a background thread. One WebSocket registration shared by every tab.

🔌

shared.io

Runs Socket.IO in a background thread. One data connection shared by every tab for status updates, notifications, and call state.

The SharedWorker pattern

A WebWorker is a script that runs in a background thread, separate from the main page. A SharedWorker goes further: it is one worker instance shared by every tab of the same site.

Each tab connects to the worker through a PostMessage channel — a form of IPC (Inter-Process Communication). The worker holds the single SIP registration and the single Socket connection, and routes messages to whichever tab needs them.

sip.js-worker deep dive

The worker starts by creating three managers: WorkerState tracks what is happening, MessageBroker routes messages between tabs, and SipCore is the actual SIP phone engine. Notice SipCore starts as null — it is created when the first tab sends a "register" message.

sip.js-worker/src/worker/index.ts 
/**
 * Worker entry point
 */

import { MessageBroker } from './message-broker';
import { TabManager } from './tab-manager';
import { SipCore, SipCoreOptions } from './sip-core';
import { WorkerState } from './worker-state';
import { SipWorker, VERSION } from '../common/types';

// Khởi tạo WorkerState
const workerState = new WorkerState();

// Khởi tạo MessageBroker
const messageBroker = new MessageBroker();

// Set WorkerState reference cho MessageBroker
messageBroker.setWorkerState(workerState);

// Biến lưu trữ SipCore
let sipCore: SipCore | null = null;
PLAIN ENGLISH

The SharedWorker starts by creating three managers: WorkerState (tracks what is happening), MessageBroker (routes messages between tabs), and SipCore (the SIP phone engine).

The Vietnamese comments say "Initialize WorkerState", "Initialize MessageBroker", "Set WorkerState reference for MessageBroker", and "Variable to store SipCore".

Notice SipCore starts as null — it is not created until the first tab sends a "register" message. This means the SIP connection is lazy: no resources are used until an agent actually needs the phone.

The TabManager watches for tabs closing. If a tab closes while on a call, it auto-hangs-up — nobody is listening anymore. It also tracks the AudioContext — browsers suspend audio when no user interaction happens, so the worker needs to know when audio state changes.

sip.js-worker/src/worker/index.ts 
const tabManager = new TabManager(messageBroker, workerState, {
  onTabClosedWithCall: async (callId: string, reason: string) => {
    if (sipCore) {
      console.log(`Auto-hanging up call ${callId} due to: ${reason}`);
      await sipCore.hangupCall(callId);
    } else {
      console.error(`Cannot hangup call ${callId}: SipCore not initialized`);
    }
  },
  onAudioContextStateChanged: (hasRunningAudioContext: boolean, previousState: boolean) => {
    if (sipCore) {
      console.log(`AudioContext state changed: ${previousState} → ${hasRunningAudioContext}`);
      sipCore.handleAudioContextStateChange(hasRunningAudioContext, previousState);
    }
  }
});
PLAIN ENGLISH

The TabManager receives two callbacks: one for when a tab closes during a call (auto-hang-up), and one for when audio state changes (resume or suspend).

onTabClosedWithCall: if a tab closes while on a call, the worker automatically hangs up — no orphaned SIP session left behind.

onAudioContextStateChanged: the browser may suspend audio after idle. When audio resumes, the worker notifies SipCore so it can re-establish the audio path.

SipCore: the SIP phone engine

SipCore imports from sip.js — the SIP library that provides all the building blocks for making and receiving calls over WebSocket.

The LenientTransport is a custom patch that fixes real-world WebSocket quirks that the standard library does not handle.

The Vietnamese comment at the top says "SipCore — SIP signaling handler class".

UserAgent is the phone identity — it tells the server who is registering. Registerer sends the "I am online" message to FreeSWITCH.

Inviter starts an outbound call. Invitation handles an inbound call. Session and SessionState track the call lifecycle (ringing, answered, terminated).

LenientTransport is a custom WebSocket transport that patches real-world quirks — some proxies strip headers or send malformed frames that the standard library rejects.

shared.io: Socket.IO over SharedWorker

shared.io creates four managers: MessageRouter directs messages, AckManager tracks request/response pairs, NotificationManager broadcasts events to all tabs, and LongPollingManager provides a long-polling fallback for browsers without SharedWorker support.

When a tab connects, it sends a PostMessage port — the worker uses this private channel to talk to that specific tab.

shared.io/src/worker/index.ts 
/**
 * Shared Worker Entry Point
 *
 * This module is the entry point for the Shared Worker,
 * handling connections from clients and coordinating messages.
 */

import { MessageType, WorkerMessage } from '../common/types';
import { createMessageRouter, IMessageRouter } from './message-router';
import { createSocketManager, ISocketManager } from './socket-manager';
import { createAckManager, IAckManager } from './ack-manager';
import { createNotificationManager, INotificationManager } from './notification';
import { createLongPollingManager, ILongPollingManager } from './long-polling';

// Initialize managers
const messageRouter: IMessageRouter = createMessageRouter();
const ackManager: IAckManager = createAckManager();
const notificationManager: INotificationManager = createNotificationManager(messageRouter);
const longPollingManager: ILongPollingManager = createLongPollingManager(messageRouter);
const socketManager: ISocketManager = createSocketManager(
  messageRouter,
  ackManager,
  notificationManager,
  longPollingManager
);

/**
 * Initialize the Shared Worker
 */
export function initializeWorker(): void {
  try {
    // Listen for connection events from clients
    self.addEventListener('connect', (event: MessageEvent) => {
      handleConnect(event.ports[0]);
    });

    console.log('Socket.IO Shared Worker initialized');
  } catch (error) {
    console.error('Could not initialize Shared Worker:', error);
  }
}
PLAIN ENGLISH

Four managers are created at startup: MessageRouter (directs messages), AckManager (tracks request/response pairs via ACK), NotificationManager (broadcasts to all tabs), and LongPollingManager (fallback).

self.addEventListener('connect', ...) is how a SharedWorker receives new tab connections. Each tab sends a MessagePort — a private, two-way channel between that tab and the worker.

The Vietnamese comment says "Listen for connection events from clients" and "Initialize the Shared Worker".

SocketManager: the gateway

The SocketManager interface is the gateway between the SharedWorker and the Socket.IO server. Every tab calls connect, emit, on through this single manager.

The key method is emitWithAck — the ACK-based request/response pattern: send a message and wait for the server to acknowledge it.

shared.io/src/worker/socket-manager.ts 
export interface ISocketManager {
  connect(url: string, options: SharedSocketIOOptions, message: WorkerMessage): void;
  disconnect(message: WorkerMessage): void;
  emit(eventName: string, args: any[], message: WorkerMessage): void;
  emitWithAck(eventName: string, args: any[], message: WorkerMessage): Promise<any>;
  on(eventName: string, message: WorkerMessage): void;
  off(eventName: string, message: WorkerMessage): void;
  once(eventName: string, message: WorkerMessage): void;
  getConnectionStatus(): ConnectionStatus;
}
PLAIN ENGLISH

connect / disconnect: open or close the Socket.IO connection to the backend server.

emit: fire-and-forget — send a message to the server without waiting for a response.

emitWithAck: request/response — send a message and get a Promise that resolves when the server acknowledges it. This is how reliable data flows work.

on / off / once: subscribe, unsubscribe, or listen once to server events — the same pattern as a DOM event listener.

getConnectionStatus: check whether the socket is currently connected, reconnecting, or disconnected.

How they work together

sip.js-worker handles the call lifecycle: ringing, answering, talking, hanging up. shared.io handles everything else: agent status updates, queue notifications, CDR display.

They are independent — either can work without the other — but together they give the browser agent a complete real-time experience that survives tab switches.

📡

sip.js-worker owns

SIP registration with FreeSWITCH. Call setup (INVITE). Call teardown (BYE). WebRTC media negotiation. AudioContext state management.

🔌

shared.io owns

Agent status (available, on-call, break). Queue notifications (new call waiting). CDR display (call records). Any real-time data the UI needs to stay in sync with the backend.
